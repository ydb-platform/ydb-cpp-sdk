# ODBC consumer verification

The matrix installs the same packaged driver in isolated YDB jobs. It runs after merge
into `odbc-driver-feature`, or on a pull request labelled `ODBC full matrix`.
The native SDK/compiler/YDB-version matrix remains separate.

| Consumer | Upstream suite |
| --- | --- |
| package-contract | Debian installation, upgrade, removal and replacement |
| isql | unixODBC scalar-query smoke test (DSN) |
| Qt | QtSql database, query, model and threading tests |
| PHP | ext/odbc PHPT tests |
| PHP PDO | PDO_ODBC and generic PDO PHPT tests |
| Ruby | ruby-odbc ANSI and UTF-8 tests |
| Lua | LuaSQL ODBC tests |
| R | odbc generic tests and DBItest's standard ODBC contract |

All bindings run in DSN and connection-string modes. R's Arrow and stress suites are
separate APIs and are outside this ODBC contract. Julia and Tcl are outside the ticket.

## Sources and fixtures

Runtime bases and YDB are digest-pinned. Consumers with archived upstream suites
have checksum-locked source archives and `upstream.lock`. `package-contract` and
`isql` use installed system packages. PHP sources match the installed Ubuntu runtime
release. Ruby, Lua and R bindings build from their locked source.
R additionally locks DBItest in `test-sources.lock`.

Sources are downloaded only into the test container, checked before extraction, and
kept out of SDK packages. Fixture patches apply to writable copies. They may change
schema, dialect, connection setup or test reporting; assertions must retain their
behavior. Binding implementations are unchanged except for the temporary LuaSQL
backport below. R's DBItest fixture patch adds required keys
and YQL literals; SQL generated by bindings still exercises their original code.
Qt source uses its GPL-3.0 Qt exception option
only in CI and is not distributed in SDK artifacts.

Lua additionally applies `upstream.patch`, a temporary backport of
[LuaSQL #219](https://github.com/lunarmodules/luasql/pull/219).
Remove the patch and its apply step when the pinned source includes the fix.

Reports retain source revisions, archive and fixture checksums, runtime package
versions, driver commit, package checksum, YDB image and connection mode.

## Results and exceptions

Adapters discover an inventory before execution and report native `results.json` with
`inventory` and `tests`. IDs include the consumer and connection mode. Missing cases,
invalid output, crashes, setup errors, unexplained skips and unexpected passes fail
validation. Framework data rows and diagnostics remain in native output and attachments.
Qt also checks data-row counts against its pinned source and fixture profile.

Every applicable test must pass. Only fundamentally unsupported functionality or
explicitly inapplicable backend/platform cases may be classified. Driver and binding
defects remain failures. Never classify a broken fixture or missing dependency.

```yaml
classifications:
  - outcome: unsupported
    reason: Explain the fundamental limitation.
    match: 'A stable diagnostic identifying the unsupported operation'
    tests:
      consumer: [consumer.*.suite.case]
```

`unsupported` requires a failed test; `skipped` requires an upstream skip. Every
reported problem must match the diagnostic. `broken` and setup failures are never
expected. Patterns must match results, must not overlap, and must not exempt entire
suites. Raw status, message and trace are preserved; Allure adds the classification
separately. A changed diagnostic or a newly passing exception requires review.

Aggregation requires every registered run and matching driver/package/YDB provenance.
It preserves attachment filenames and reports passes, expected limitations/skips and
unexpected outcomes separately. Genuine compatibility gaps keep the matrix red.

## Running

Validate the registry and harness:

```sh
python3 odbc/tests/frameworks/harness.py registry
python3 -m unittest odbc.tests.test_integration_harness
```

Use `harness.py launch --consumer NAME --mode dsn --runtime-image IMAGE --package FILE
--results DIRECTORY` with `DRIVER_COMMIT`, `YDB_TEST_IMAGE`, `YDB_ENDPOINT` and
`YDB_DATABASE` set. The image must match the registry. Use `connection_string` for
the second mode and `all` for package-contract. The launcher needs Docker access.
The full CI matrix and report aggregation come from the registry.
